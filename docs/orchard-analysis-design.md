# 園地分析（時系列カルテ）

## データ経路

`AnalysisDataRepository` → `AnalysisDataRecord[]` → `buildOrchardAnalysis()` → 園地分析UI

画面は検索、並び替え、年度区切りを独自に実装しない。Domainが返す時系列エントリをそのまま表示する。

## 検索と並び順

- 園地・品種カテゴリは必須条件、処理区は任意（初期値はすべて）
- 品種は共通の品種別名マスタでカテゴリ化して検索する。たとえば「早生」「山下紅」は同じ早生カテゴリに含める
- 分析対象は `正常` と観測項目欠測状態（`横径なし`、`糖度なし`、`酸度なし`）のみ。`要確認`、取消・削除・未知の状態は表示しない
- 検索候補は園地 → 品種カテゴリ → 処理区の順で連動する。上位条件の変更時は、下位条件を有効な最初の候補または「すべて」へ戻す
- 処理区が「すべて」の場合は、比較のため処理区列を日付の右側に表示する。個別処理区を選択した場合は非表示にする
- 1行は1回の調査。同日の複数レコードも集約しない
- 計測日降順、同日の場合は登録日時降順、登録ID昇順で安定化する
- 計測日が欠測のレコードは時系列に配置できないため表示対象外とする
- 年度の切替位置に見出しを挿入する

## 表示列

横径・糖度・酸度の実測値に加え、収穫時予測3列と気象2列を表示列として確保する。
予測エンジンと気象集計基盤は本機能の対象外のため、これら5列の値は常に `—` とする。

## UI制約

- スマホ優先の高密度テーブル
- 左固定列は日付のみ。表全体を単一の横スクロール領域に配置し、列ヘッダーと全行は常に同じ横位置を共有する
- 検索条件と列ヘッダーをSticky表示する
- 表示項目は画面内でON/OFFできる（永続化しない）

## 2園地比較（指示書 No.041）

- 日付を左から右へ昇順に並べ、指標ごとに園地A・園地Bの2行を表示する
- 対象指標は平均・最小・最大横径、糖度、クエン酸、糖酸比
- 同一日だけを同じ日付列に置く。近い日付は対応付けず、同日の複数レコードも平均化せず別列で保持する
- 欠測は `—` とし、0への変換、補間、平均化をしない
- 園地Aは淡い青、園地Bは淡いオレンジに加え、園地名を必ず文字表示する
- 指標・園地列と日付見出しを固定し、表だけを横スクロールする
- 指標グループ、見出し、年の切替を罫線で区切る
- 最新値カードは各園地の最終計測日を個別に明示する
- 390px幅を基準とし、ページ全体は横スクロールさせない
