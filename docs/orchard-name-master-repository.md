# 園地名正規化マスタ読取契約

## 対象と境界

- Spreadsheetタイトルは `定期調査Output園地マスタ`、対象シートは `園地名正規化マスタ`、取得範囲は `A:K` に固定する。
- サーバー専用Repositoryが既存Reader認証と `spreadsheets.readonly` スコープでGETする。
- targetはサーバー専用の `ORCHARD_MASTER_SPREADSHEET_ID` で指定し、呼出側から任意Spreadsheet、シート、範囲を渡さない。
- Writer資格情報、書込みHTTPメソッド、公開経路へのフォールバックを使用しない。
- 認証情報、Spreadsheet ID全体、セル内容をエラーやブラウザーへ出さない。

## 2026-08-02 Preflight

正式11列、データ172行を読取専用で確認した。原園地名の空欄・重複は0件、確認状態は全172行が `確認済み`、確認済み行の正式園地名欠測は0件だった。正式園地名は確認後列15件、候補列へのフォールバック157件、処理区は確認後列7件、候補列へのフォールバック57件である。ユーザー入力値は変更していない。

## 適用規則

- `確認済み`だけを正規化へ使用する。
- 正式園地名は `確認後正式園地名`、空欄時は `正式園地名候補` の順で採用する。
- 処理区は**レコード自身の処理区を常に優先**する。1つの園地に実際には10種類前後の処理区が存在しうるため、マスタは単一の処理区を持てず、レコードの処理区を上書きしてはならない。
- レコード自身の処理区が空欄の場合に限り、`確認後処理区`、空欄時は `処理区候補` で補う。両方空欄なら処理区なしのままとする。
- `未確認`、`保留`、`統合しない`はInput原園地名を表示し、処理区を推測しない。
- 同一の原園地名に複数行があれば契約違反として拒否し、自動統合しない。
- 正規化前の園地名は表示上の追跡用に保持する。登録ID、品種、日付、調査値、予測値、前回差は変更しない。
- 正式園地名が同じでも処理区が異なるレコードは別の選択単位とし、平均・混合しない。

## 障害時

園地マスタだけの取得・契約エラーではInput分析を停止しない。Input原表記を維持し、画面上部へ固定のサニタイズ済み警告を1件だけ表示する。値を推測補正せず、公開経路へフォールバックしない。

## 園地選択順

- 園地と処理区の組を安定した選択キーにする。
- 選択期間内の最新 `measuredAt` 降順、同日は正式園地名昇順、同名は処理区昇順とする。
- 全年では全期間、年指定時はその年の最新日で再計算する。
- 有効な計測日がない園地は全年表示の末尾に置く。年指定時は所属年を決められないため候補外とする。
- `registeredAt`、Input行順、配列位置を並び順やIDへ使用しない。

## 将来拡張

降水量地点と気温地点をマッピング型に予約するが、現行シートに正式列がない間は常に未設定とする。地点を園地名から推測しない。
